# OCC's Mission & Goals

Инструмент учёта обновлений и исправлений для ONC Compiler Collection: помогает быстро фиксировать записи и сразу видеть, что ещё не сделано.
Два режима: графический интерфейс на WPF для повседневной работы и CLI, выводящий стандартный JSON для интеграции с AI / скриптами / CI.

# Установка

### Скачивание

Готовые установщики публикуются на странице [Releases](https://github.com/CialloForMyCode/OCC-s-Mission-Goals/releases/latest).
Оба варианта самодостаточны — .NET runtime не требуется:

| Архитектура | Установщик |
|-------------|------------|
| x64 (рекомендуется) | `OCC-Mission-Goals-<версия>-x64-setup.exe` |
| x86 | `OCC-Mission-Goals-<версия>-x86-setup.exe` |

### Требования

| Компонент | Требование |
|-----------|------------|
| Операционная система | Windows 10 / 11 |
| Runtime для установщика | не нужен (самодостаточная сборка) |
| Runtime для сборки из исходников | [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) |

### Сборка

```bash
git clone https://github.com/CialloForMyCode/OCC-s-Mission-Goals.git
cd "OCC-s-Mission-Goals"
dotnet build
```

### Запуск

```bash
# Режим GUI
dotnet run

# Режим CLI (показать справку)
dotnet run -- -h
```

### Сборка установщика

```bash
installer\build-installer.cmd
```

Требуется [Inno Setup 6](https://jrsoftware.org/isinfo.php); результат попадает в `output/`.

Никаких сторонних зависимостей NuGet — чистый .NET 8 + WPF, работает сразу после сборки.

# Использование

### Основной процесс

1. **Создать проект** — меню → Новый проект (`Ctrl+N`): имя, описание, начальная версия
2. **Создать версию** — диалог версий итерирует номер (например `0.1.0-alpha.1` → `0.1.0-alpha.2`)
3. **Добавить записи** — панель → Новая запись: заголовок, серьёзность, теги типов и блоки содержимого
4. **Отслеживать прогресс** — работа со записями на странице «Незавершённые»
5. **Завершить и архивировать** — завершённые записи переходят на страницу «Завершённые»; версию можно архивировать, когда все её записи завершены
6. **Управление проектом** — Настройки → Информация о проекте: изменить имя и описание либо удалить текущий проект (удаляются все версии и записи, безвозвратно)

### Страницы

| Страница | Назначение |
|----------|------------|
| Панель управления | Распределение по серьёзности, график динамики за 30 дней, статистика выполнения и обзор состояния проекта |
| Незавершённые | Все ожидающие записи, сгруппированные по версиям: поиск, сортировка, правка, завершение, удаление |
| Завершённые | Завершённые записи по версиям: отмена завершения, правка, удаление, архивация версии |
| Центр расширений | Установка и удаление языковых пакетов, тем и расширений с индикатором прогресса; установленные элементы сверяются с репозиторием и обновляются одной кнопкой |
| Справка | Полное руководство: основные операции, горячие клавиши, поля, справочник CLI |

### Содержимое записи

Текст записи собирается из блоков с изменяемым порядком, а не из одного блока Markdown.
Перетаскивайте маркер слева для сортировки, `+` добавляет дочерний блок:

| Блок | Описание |
|------|----------|
| Текст | Заголовки `#`, полужирный, курсив, зачёркивание, нумерованные и маркированные списки |
| Таблица | Строка заголовков и произвольные строки |
| Разделитель | Горизонтальная линия |
| Код | Язык (необязательно) и номера строк |
| Ссылка на файл | Путь + строка / столбец / функция |
| Многоуровневый список | Вложенные пункты |
| Подзадача | Пункты с флажками, задающие процент выполнения записи |

При сохранении записи связанные файлы и процент выполнения собираются из содержимого автоматически.

### Сортировка

| Сортировка | Описание |
|------------|----------|
| По серьёзности, возрастание | Fatal → Update |
| По серьёзности, убывание | Update → Fatal |
| По версии, возрастание | По строке версии, по возрастанию |
| По версии, убывание | По строке версии, по убыванию |
| По типу, возрастание | По первому тегу типа, по алфавиту |
| Только избранные | Только избранные записи, отсортированные по серьёзности |

### Уровни серьёзности

| Значение | Метка | Описание |
|----------|-------|----------|
| `Fatal` | красная | Критический, немедленное действие |
| `Severe` | оранжевая | Высокий приоритет |
| `General` | жёлтая | По умолчанию |
| `Patch` | зелёная | Мелкое исправление |
| `Update` | синяя | Обновление функционала |

### Поиск

Строка поиска фильтрует текущий список по мере ввода; префикс переключает режим сопоставления:

| Префикс | Область поиска |
|---------|----------------|
| `Text:` | Заголовок и краткое описание (по умолчанию без префикса) |
| `Tag:` | Теги типов |
| `Setting:` | Пункты настроек (проект / тема / статистика); Enter выполняет выбранный пункт |
| `Function:` | Команды: новая запись, новый проект, открыть проект |
| `File:` | Пути связанных файлов |
| `Date:` | Даты |
| `Plugins:` | Все плагины центра расширений (глобальный поиск) |
| `Expand:` | Только установленные плагины (глобальный поиск) |

### Хранение данных

Все данные хранятся в папке `Projects/` рядом с исполняемым файлом:

```
Projects/
└── <ИмяПроекта>/
    ├── project.json              # Метаданные проекта
    └── versions/
        ├── 0.1.0-alpha.0.json    # Файлы данных версий
        ├── 0.2.0-alpha.0.json
        └── archive/              # Архивные версии
```

Идентификаторы записей имеют вид `PPPEEEEEE` (9 цифр): первые 3 — номер проекта, последние 6 — автоинкремент.

### Хранение расширений

Языковые пакеты, темы и расширения, установленные из центра расширений, хранятся рядом с исполняемым файлом:

```
Languages/            # Языковые пакеты (*.xaml)
Themes/               # Темы (*.xaml)
Expand/<имя>/         # Расширения: манифест expand.json и, при необходимости, XAML
```

Расширение может переопределять ключи ресурсов (цвета, радиус скругления, толщину рамок…) или подставлять фрагменты разметки вместо части основного содержимого.

### Два режима

Точка входа `Main` проверяет аргументы запуска: без аргументов стартует **GUI** (окно WPF), с аргументами — **CLI** (вывод в консоль).
GUI и CLI — независимые процессы, доступ к данным они сериализуют через именованный межпроцессный мьютекс, поэтому могут работать одновременно без потери изменений.

# CLI команды

Режим CLI рассчитан на AI / скрипты / CI. По умолчанию выводится читаемый текст, с флагом `--json` — стандартный JSON. Ошибки идут в stderr.

```
OCCMissionGoals.exe [глобальные опции] <команда> [подкоманда] [аргументы]
```

### Глобальные опции

| Флаг | Описание |
|------|----------|
| `-p`, `--project <имя>` | Целевой проект (имя папки или имя проекта) |
| `--json` | Выводить JSON вместо читаемого текста |
| `--version <версия>` | Прочитать указанную версию, не переключаясь на неё |
| `-h`, `--help` | Справка; добавьте к команде (`entry --help`) для подробностей |

### project — управление проектами

| Использование | Описание |
|---------------|----------|
| `project list` | Список всех проектов |
| `project info [имя]` | Информация о проекте (по умолчанию — проект из `-p`) |

### version — управление версиями

| Использование | Описание |
|---------------|----------|
| `version list` | Список всех версий (`*` — текущая) |
| `version current` | Показать текущую версию |
| `version switch <версия>` | Переключиться на версию (сохраняется) |
| `version iterate` | Инкремент пре-релиза (`0.1.0-alpha.0` → `0.1.0-alpha.1`) |
| `version delete <версия>` | Удалить версию (текущую удалить нельзя) |
| `version archive <версия>` | Архивировать в `versions/archive/` (все записи должны быть завершены) |

### entry — управление записями

| Команда | Описание |
|---------|----------|
| `entry list` | Список записей |
| `entry show <id\|индекс\|заголовок>` | Показать одну запись (JSON) |
| `entry add` | Добавить запись |
| `entry edit <id\|индекс\|заголовок>` | Изменить запись |
| `entry done <id\|индекс\|заголовок>` | Отметить как завершённую |
| `entry undone <id\|индекс\|заголовок>` | Снять отметку завершения |
| `entry delete <id\|индекс\|заголовок>` | Удалить запись (безвозвратно) |
| `entry favorite <id\|индекс\|заголовок> <true\|false>` | Избранное |

Полный синтаксис:

```
entry list     [--type u|f|a] [--search <ключевое слово>] [--tag <тег>] [--favorite] [--all] [--version <версия>]
entry show     <id|индекс|заголовок> [--type u|f] [--version <версия>]
entry add      --title <заголовок> [--severity <уровень>] [--brief <кратко>] [--type <тег1,тег2>]
               [--favorite] [--version <версия>]
entry edit     <id|индекс|заголовок> [--title ...] [--severity ...] [--brief ...] [--type ...]
               [--favorite|--unfavorite] [--version <версия>]
```

`<id|индекс|заголовок>` принимает скрытый идентификатор (`001000001`), индекс в списке или точное совпадение заголовка.
`--type` задаёт область в `list` / `show` (`u` — незавершённые, `f` — завершённые, `a` — все) и теги типов (через запятую) в `add` / `edit`.

### tag — управление тегами

Управляют тегами типов текущего проекта; изменения синхронизируются с записями всех версий.

| Использование | Описание |
|---------------|----------|
| `tag list` | Список всех тегов (с цветами) |
| `tag add <имя> [--color <hex>]` | Создать тег |
| `tag delete <имя>` | Удалить тег и убрать его из всех записей |
| `tag rename <старое> <новое>` | Переименовать тег и синхронизировать все записи |

### Старый синтаксис

Старые однобуквенные флаги по-прежнему поддерживаются:

```
-a/--add   -c/--check   -d/--done   -u/--undone   -D/--delete
-f/--favorited   -l/--list   -v <версия|Iterate|Delete|Archive>
```

`-a` / `--add` дополнительно принимает старую JSON-форму: `-a {Title="...", Severity="Fatal", ...}`

### Примеры

```bash
# Список всех записей проекта "ONC"
OCCMissionGoals.exe -p ONC entry list

# Добавить критический баг
OCCMissionGoals.exe -p ONC entry add --title "NullReferenceException при запуске" --severity Fatal --brief "Падение на старте" --type Bug --version 0.1.0-alpha.0

# Машиночитаемый вывод
OCCMissionGoals.exe -p ONC --json entry list

# Отметить как завершённую
OCCMissionGoals.exe -p ONC entry done 001000001

# Сменить версию и добавить запись
OCCMissionGoals.exe -p ONC version switch 0.2.0-alpha.0
OCCMissionGoals.exe -p ONC entry add --title "Добавить вход" --severity Update

# Теги
OCCMissionGoals.exe -p ONC tag add UI --color "#3D9DE8"
```

### Модель данных

```
project.json        → ProjectConfig (Name, Description, CurrentVersion, ProjectNumber,
                                      TypeOptions, TypeColors, NextEntryId, StatsVersions, CreatedAt)
versions/*.json     → DataFile (User, Entries[])      # незавершённые / завершённые по Entry.Status
каждая запись       → GoalEntry
```

Поля записи:

| Поле | Тип JSON | Описание |
|------|----------|----------|
| `Id` | `string` | Скрытый идентификатор `PPPEEEEEE` (9 цифр); стабильная ссылка на запись |
| `Title` | `string` | Заголовок (единственное обязательное поле) |
| `Severity` | `string` | `Fatal` / `Severe` / `General` / `Patch` / `Update` |
| `Status` | `string` | `Unfinished` / `Finished` |
| `Brief` | `string` | Краткое описание |
| `Contents` | `ContentBlock[]` | Тело записи: упорядоченные блоки (текст / таблица / разделитель / код / ссылка на файл / многоуровневый список / подзадача) |
| `Progress` | `int` | Выполнение 0–100, выводится из блоков «подзадача» (пункты списков не учитываются); обновляется при сохранении и пересчитывается при загрузке |
| `CompletedAt` | `string` (ISO 8601) | Время завершения; пусто, пока запись не завершена |
| `CreatedAt` | `string` (ISO 8601) | Время создания |
| `UpdatedAt` | `string` (ISO 8601) | Время последнего изменения |
| `IsFavorited` | `bool` | Избранное |
| `Type` | `string[]` | Теги типов (Bug, UI, Feature, …) |
